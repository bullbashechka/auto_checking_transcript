# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## ⚠️ Что НЕЛЬЗЯ трогать

- **`.env`** — содержит секретные ключи (TELEGRAM_TOKEN, OPENAI_API_KEY). Никогда не читай, не выводи, не редактируй и не коммить этот файл. Если нужно что-то поменять — отредактируй `.env.example` и попроси пользователя обновить `.env` руками.
- **Реальные xlsx-табели** в корне (например `Сайдашев Кирилл Алексеевич.xlsx`) — это рабочие данные клиента. Можно читать для тестирования парсера, но не переименовывать и не модифицировать на месте. Результат всегда пишется отдельным файлом `{stem}_исправленное_{дата}.xlsx`.

## Команды

Запуск всегда из venv **и из корня проекта** (CWD = `auto_checking_transcript/`). Все `python -m ...` команды используют `from src import ...`, который опирается на CWD в `sys.path`:

```bash
source .venv/bin/activate
```

| Команда | Назначение |
|---|---|
| `pip install -r requirements.txt` | поставить зависимости |
| `python -m src.main` | запустить Telegram-бота (long polling) |
| `python -m scripts.check_file <path.xlsx>` | прогнать проверку локально без Telegram |
| `python -m unittest discover tests` | запустить все юнит-тесты |
| `python -m py_compile src/*.py scripts/*.py tests/*.py` | быстрая синтаксическая проверка |

Линтеров пока нет — добавлять только если просит пользователь.

## Архитектура

Конвейер обработки одного xlsx-табеля:

```
bot.handle_document  →  checker.process_file
                              │
              xlsx_processor.parse(path)  → list[WorkEntry]
                              │
              llm.LLMClient.check(...)  ← конкурентно через Semaphore(LLM_CONCURRENCY)
                              │
              xlsx_processor.write_result(...)  → новый файл с подсветкой
                              │
                          Report.render()  → текст в Telegram
```

### Что важно понимать сразу

**1. Двухуровневая структура входного xlsx.**
Файл — не плоская таблица. В `src/xlsx_processor.py:parse` колонка «Содержание» ищется по заголовку, дальше итерация снизу:
- если ячейка «Содержание» **пустая**, а в колонке A что-то есть → это **строка-заголовок контрагента**, имя запоминается;
- если «Содержание» **заполнено** → это строка работы, к ней приклеивается последний запомненный контрагент.

Без этого нельзя корректно передавать в LLM поле `Контрагент`. Колонка «Содержание» — единственное проверяемое поле.

**2. Вся логика проверки — в системном промте, не в коде.**
`src/prompts/system_prompt.txt` определяет правила орфографии, эталонный словарь регистра аббревиатур (1С, ИБ, ЭСФ, …), список «не трогать» (кавычки, фамилии после «пользователь», номера версий) и распознавание незаполненных placeholder'ов (`(чей ПК)`, `3.0.....`, `(название ИБ)`). Если поведение модели нужно поправить — почти всегда правится промт, а не Python.

LLM возвращает строгий JSON одной из четырёх форм (пусто / только исправление / только предупреждение / оба). Маппинг JSON→Python в `CheckResult` (поля русские, с алиасами).

**3. Результат в xlsx — это новый файл с подсветкой.**
- Исправленные ячейки → жёлтая заливка (`HIGHLIGHT_FILL`).
- Предупреждения о placeholder'ах → красноватая заливка (`WARNING_FILL`), текст **не** изменяется.
- Имя выходного файла: `{stem}_исправленное_{YYYY-MM-DD}.xlsx` — формат фиксирован, не меняй без согласования.

**4. Доступ к боту — whitelist по Telegram ID.**
`Settings.allowed_user_ids` из env. Если whitelist пуст — бот открыт всем (режим локальной отладки). Команда `/id` всегда возвращает Telegram ID — её используют, чтобы добавить себя в whitelist.

**5. Async + лимиты OpenAI.**
LLM-батчи до 15 строк запускаются через `asyncio.gather`. `Semaphore(LLM_CONCURRENCY)` ограничивает одновременные соединения, а общий token-pacer резервирует не более 80% настроенного TPM. 429 повторяется с серверной задержкой и jitter; одиночный fallback для rate-limit не выполняется.

### Когда нужно править Python, а когда промт

| Нужно | Где править |
|---|---|
| Добавить новую аббревиатуру в эталонный словарь | `system_prompt.txt` |
| Расширить список placeholder-конструкций | `system_prompt.txt` |
| Поменять формат ответа модели | `system_prompt.txt` + `CheckResult` в `llm.py` |
| Поменять модель OpenAI | `.env` (`OPENAI_MODEL`) |
| Изменить структуру входного xlsx (другие колонки) | `xlsx_processor.py:parse` |
| Поменять имя выходного файла или подсветку | `xlsx_processor.py:write_result` |
| Добавить новый Telegram-хендлер | `bot.py:build_application` |
